Sam & Co, barbers

This page is deliberately plain. It has no framework, no build step and no styling worth mentioning, because the thing being demonstrated is that a shop does not need any of that: one <script> tag, and a visitor can both talk to somebody and book a time.

One tag, not two. Booking is reached through the widget the shop already embeds — a small chip in the panel header that inserts and sends /booking, exactly as if the visitor had typed it. That is 20-06's embed decision, settled on product grounds rather than packaging ones: booking has to work from Telegram, MAX and SMS as well, where there is no widget at all, so a booking-only embed would be the one shape the product model rules out.

20-07 moved the booking flow itself behind the chat contract: the visitor's whole conversation with AGO Calendar — the questions, the choices, the confirmation — now arrives as ordinary chat messages carrying a closed set of primitives (adr/0065), the same way it would over a text-only channel. This widget makes no direct request to AGO Calendar at all; everything rides the one connection it already holds to Ago.Chat.Api.

What the shop pastes

<script src="https://…/widget.js"
        data-site="demo_site"
        data-api="http://localhost:5009"
        async></script>

Nothing in that tag mentions booking. It went from 20-06's two required attributes (a calendar tenant key and a calendar API origin), to 22-22's one boolean, to none: 23-105 removed data-booking entirely. Booking is an entitlement the platform grants (adr/0151), not a claim a shop's own HTML is in any position to make — so it arrives on the visitor-session handshake next to the colour, the position and the locale, and this page gains the chip the moment the grant lands, untouched. A page still carrying the old attribute gets nothing from it.

Running it against the local stack

This page is served from a different origin than the chat API, on purpose — the CORS model is only exercised by a genuinely cross-origin page. The tenant’s allowed_origins must contain whatever origin serves this file, or the browser refuses the response. See ago-root/docs/runbooks/local-dev.md.
